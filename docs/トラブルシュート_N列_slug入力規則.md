# N列（slug）「入力規則に違反しています」

## 原因

N列に **入力規則（プルダウン）** が設定されており、**既存の slug 一覧だけ**が許可されています。

`hokkaido-sports-college` など **Y列で新しく作った候補**はリストに無いため、拒否されます。

これは初期構築時に「slug を選ぶだけ」にした名残です。  
**現在の運用（Y列で候補 → N列に確定）** とは矛盾するため、**入力規則は削除して問題ありません。**

---

## 推奨：N列の入力規則を削除する

| 項目 | 内容 |
|------|------|
| 削除してよいか | **はい**（推奨） |
| 理由 | N列は **自由入力の確定値**。Y列が候補、N列は手で確定する設計 |
| 既存44件への影響 | **なし**（すでに入っている値はそのまま） |
| サイト側 | slug 列の文字列を読むだけ。プルダウンは不要 |

### 手順（Googleスプレッドシート）

1. **シート1** を開く
2. **N列**のデータ行を選択（例: **N2:N** または N2〜最終行）
3. メニュー **データ** → **入力規則**（データの入力規則）
4. 右パネル下部の **入力規則を削除**（ゴミ箱アイコン）→ **完了**

5. Y列の候補をコピー → 対象行の N列に **値のみ貼り付け**

---

## 代替案（入力規則を残したい場合）

### A. 拒否 → 警告に変更（暫定）

1. N列を選択 → **データ** → **入力規則**
2. **無効なデータが入力された場合**
   - 「入力を拒否する」→ **「警告を表示する」** に変更
3. リストにない slug も入力可能（警告は出るが保存できる）

### B. プルダウンのリストを増やす（非推奨）

入力規則の「リストの範囲」に、新しい slug を **都度追加**する方法。

- 投稿のたびにリスト更新が必要で手間が大きい
- Y列自動候補の運用と相性が悪い

### C. 形式チェックだけに置き換え（上級者向け）

プルダウンではなく **カスタム数式** で kebab-case のみ許可:

```text
=OR(LEN(N2)=0, REGEXMATCH(N2, "^[a-z0-9-]+$"))
```

- **無効な場合:** 「警告を表示」（拒否しない）
- 新規 slug は通る。大文字・スペース・日本語は警告

---

## 入力規則の確認方法

1. N列のセル（例: N46）をクリック
2. **データ** → **入力規則**
3. 右パネルで次を確認:
   - **条件:** 「プルダウン」または「リストから選択」
   - **範囲:** 既存 slug が並んだ別シート・列、または直接入力された一覧

よくある設定例:

- 範囲 `=slug一覧!A2:A`（26種類の既存 slug のみ）
- 直接入力 `sapporo-fire-school, ningyo-joruri, …`

いずれも **新規 slug は含まれない** ためエラーになります。

---

## 確定後の確認

```bash
npm run verify:slugs   # 既存44件が変わっていないこと
npm run verify         # 新規 slug で URL が解決できること
```

新規行だけ `data/slug-snapshot.json` に追記する必要はありません（スナップショットは **既存保護用**）。
